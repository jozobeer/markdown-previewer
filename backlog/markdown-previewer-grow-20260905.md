
# 表の記法をレンダリングして、README や日報の表組みを崩さず確認できるようにする

いまのパーサは見出し・リスト・引用・コードブロックは解釈するが、`| 項目 | 値 |` で始まる表の記法には判定がなく、表を書くと右ペインには縦棒とハイフンの行がそのまま段落として並ぶ。GitHub の README や日報・議事録では表は見出しやリストと同じくらい頻繁に使う記法で、そこだけ確認できないと利用者は結局 GitHub に貼って見た目を確かめることになり、プレビューアとしての役目を果たせない。見出し行・区切り行（`| --- | --- |`）・本文行の並びを表として検出し、`table > thead/tbody` に変換する。区切り行のコロン位置で列の左寄せ・中央・右寄せも反映する。

## 意図

README や日報を Markdown で書く人が、GitHub や Wiki に貼る前に表の列ずれやセルの記法を手元で確かめるために使う。
表を含む文書は少なくなく、それだけ確認できないとプレビューアを開く理由が薄れるため。

## 受け入れ条件の種

- 見出し行 `| 項目 | 値 |`・区切り行 `| --- | --- |`・本文行2行（1行目のセルは `**A**` とインラインコードの `1`、2行目は `B` と `2`）を入力すると、`#preview` に `table` が1つ描画され、`thead tr th` が2つ・`tbody tr` が2行になる。区切り行は行として表示されない。セル内の `**A**` は `strong`、インラインコードは `code` に変換される
- 区切り行を `| :--- | :---: | ---: |` にすると、1列目・2列目・3列目の `th` と `td` がそれぞれ左寄せ・中央・右寄せになる（クラス名または固定の3値の style で表現し、セル本文の文字列を属性へ埋め込まない）。セル数が見出し行より少ない本文行は空の `td` で埋められ、多い行の余分なセルは捨てられる
- 縦棒を含む行の直下に区切り行がなければ、いまと同じく `p` として表示される。フェンスドコードブロック内の表記法は原文のまま表示され、セルに `<script>alert(1)</script>` を書いても文字列として表示される。`tests/app.spec.ts` の既存テストがすべて通る
